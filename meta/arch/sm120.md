## Architecture notes for this run: sm120 (RTX Blackwell, `{CARD_ARCH}`)

The worked examples in this prompt were written on sm90 / sm100 kernels. On this run's architecture read them as
below; the facts are in `{KB_READ_DIR}/index.md` (its classification table) and
`{KB_READ_DIR}/device_facts_rtx_pro_5000.md`. **Where an example elsewhere in this prompt disagrees with this section,
this section holds.**

- **MMA**: warp-level `mma.sync` only. In SASS: `HMMA` (f16 / bf16), `QMMA` (FP8) and `QMMA.SF` (MXF8 block-scaled),
  `OMMA.SF` (NVF4 block-scaled), `IMMA`. There is no `wgmma` (`HGMMA`, `WARPGROUP.ARRIVE/DEPBAR`, the warpgroup as
  an MMA unit) and no `tcgen05` / TMEM / `UTC*MMA`. Where a fingerprint table says `HGMMA.<M>x<N>x<K>`, the tensor
  kernel is recognised by its `mma.sync` family instead, and the accumulator lives in registers (2-4 per issue per
  thread). "The kernel must be WGMMA / TMA code" reads "tensor-core code built from this architecture's primitives".
- **Supply and schedule objects**: cp.async (`LDGSTS`, commit groups read as `LDGDEPBAR` / `DEPBAR.LE SB0, N`) or
  TMA + mbarrier (`UTMALDG`, `SYNCS` try-waits) into shared memory, then `ldmatrix` (`LDSM`); named barriers
  (`BAR.SYNC`). There is no wgmma wait depth to read. A stage that `ldmatrix` read and a TMA refill will overwrite
  needs a proxy fence before it is released.
- **Verdict lines**: `WGMMA-SERIAL` and `SASS-OPERANDS` print an explicit SKIP on this architecture; that is the
  expected line, not a failure and not a reason to waive. `SCHED-OK` reads `isa=mma_sync`; `LIVE-OK` reads
  `floor=mma_sync` (a peak of a few tens of registers is normal for a small-M mainloop).
- **Device numbers**: 110 SMs (an example that recognises a persistent grid by "132" or "148" means "the SM count":
  110 here); shared memory at most 101,376 B per CTA and 102,400 B per SM (not 227 / 228 KiB); L2 96 MiB; a block of
  384 threads is 12 warps, not "3 warpgroups of an MMA".
- **NCU on this chip (GB202)**: DRAM volume is `dram__bytes_op_read.sum` / `dram__bytes_op_write.sum`
  (`dram__bytes_read.sum` / `_write.sum` come back n/a). A cp.async fill is visible only in
  `sm__sass_l1tex_data_pipe_lsu_wavefronts_mem_shared_op_ldgsts.sum` (per `sm__sass_inst_executed_op_ldgsts.sum`:
  4 is conflict-free at 16 B per lane). mbarrier / TMA waits are counted as the `sleeping` stall, not as
  long-scoreboard.
- **Occupancy**: no simulator table ships for this architecture; an `smem.occupancy("sm_90a", ...)` call in an
  example is not valid here. Take CTAs per SM from NCU's `launch__occupancy_limit_*` or from the device numbers
  above.
- **CUDA kernel files** are compiled for `{CARD_ARCH}` by default; an explicit target goes on the
  `// fk-cuda-cflags:` line as `-gencode=arch=compute_120a,code=sm_120a` (with `=`).
